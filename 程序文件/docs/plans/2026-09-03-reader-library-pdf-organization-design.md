# 公众号文章阅读器：整理、文章库与自动 PDF 设计

## 目标

把面向日常使用的入口、文章结果与技术程序文件分开。用户双击启动器、粘贴公众号链接后，程序自动保存文章、图片与 PDF；随后可从轻量文章库界面搜索和打开历史文章。

## 目录

项目根目录只保留 `启动公众号文章阅读器.cmd`、`文章库/` 和 `程序文件/`。技术代码、Node 依赖、构建产物、专用 Edge 资料和开发文档全部移动到 `程序文件/`。文章库是唯一用户结果目录。

文章目录采用 `YYYY-MM-DD_清理后的标题`；同名冲突时追加 `（2）`、`（3）`。稳定的文章 ID 只保存在 `manifest.json`，不显示在文件夹名称中。

## 读取与 PDF

每次读取成功后，系统在文章目录自动生成 `文章.pdf`。PDF 从本地 Markdown 与已保存图片生成，不上传内容。PDF 导出失败不影响正文、图片和文章记录的保存；界面会如实显示失败原因并允许之后重新生成。

## 轻量文章库窗口

保留链接输入和“读取文章”按钮；增加文章标题搜索、历史列表、打开文章、打开文件夹和重新生成 PDF。窗口不读取剪贴板，不在后台监控链接，也不涉及账号或云同步。

## 阅读质量

优先提取真实懒加载图片地址，保存本地图片并限制类型、大小和超时。针对临时网络错误做有限重试；单张图片失败在记录中标出，但不让完整正文读取失败。保留段落、标题、列表、引用和图片替代文本。

## 验证

测试覆盖：可读目录冲突、自动 PDF 成功与失败隔离、图片重试、历史搜索、旧版数据迁移和启动器路径。最终执行全部测试、类型检查、构建、窗口启动检查和用户提供链接的真实读取验收。
