# 平台、文件导入与存储治理

目标：说明实际功能与边界，补齐合适的收集入口，使正式资料有固定位置，清理可核验的重副本并减少后续 staging 堆积。

主库继续使用项目下 `资料库/`，程序和依赖留在 `程序文件/`；原 `文章库/` 保持兼容。先核对内容与恢复路径，再回收临时文件。原始媒体、正文、字幕、机器识别数据、阅读 HTML/PDF、迁移恢复备份属于有效资料。

不创建新工作树，不改模型与账号配置，不提交 Git 或发布。成员只运行定向检查；统一构建和全量检查由主控执行。

## 完成条件

- 支持表区分已实现、样本实测、条件支持与尚未支持；不能把网页正文支持当成视频平台支持。
- 本地导入保存原件，不改变源文件；失败、取消、无可用正文/媒体不得标成成功。
- 存储报告记录正式资料、依赖、缓存、恢复材料和可回收副本的大小。
- 回收前重新核验路径、工作锁、任务终态、文件字节和 SHA-256；未知文件与不完整任务保留。
- 清理后两条真实视频、Small 转写三件套和阅读产物保持原哈希，其他正式记录不受影响；重试可从正式文件恢复。
- 运行必要定向回归、构建、类型检查和统一集成检查；实际释放空间单独记录。
