# 单一资料库、可读命名与操作入口统一

目标：保留一个日常资料库；新旧资料完整备份后整理，文章全文、阅读页、PDF及界面按钮对应同一正式条目。保留现有公众号原文排版修复及未提交修改。实现阶段先完成本地验证，后续用户授权的GitHub发布与沉淀由本记录续写。

## 约定与范围

- 正式条目继续在`资料库/items`，保留这个与队列、导出和失败恢复区的边界，不为了改名重构全部存储根。
- 第三版布局的条目文件夹采用`YYYY-MM-DD_平台_标题`，日期来自已有采集时间；同名冲突使用可读序号，稳定ID保存在清单里。
- 当前供人阅读的文件为`文章标题.html`、`文章标题.pdf`、`文章标题.md`。图片使用三位连续编号，静态图片OCR不带无意义的零时间码。图片、视频等原件直接按类型进入条目子目录，去除原始资料外壳；原始采集记录归入已有`.内部`。保留有意义的处理结果、历史与校订边界。
- `ContentListItem.textPath`指向整篇正文/完整文字稿；`transcriptPath`保留为识别稿/转写稿及校订入口。界面“打开文字稿”使用textPath，校订识别稿独立提供。
- 新旧微信API均默认解析到正式库。识别旧显式文章库路径并导向同项目正式库；旧进程另行核对，不强制关闭不相关会话。
- 完整原件、旧版本、未知staging、队列、组织信息和校订历史不作为重复垃圾删除。旧文章库核对后转入既有版本备份区，不丢弃独有文件。

## 工作顺序

1. 盘点读写方与布局；在共享维护锁下制作完整新旧资料库及当前源码恢复包，逐文件回读哈希验证。
2. 并行处理界面（窗口与窗口测试）及兼容路径（配置与具名模块）；控制器负责第三版命名、全文路径、存储整理和集成。
3. 针对全文按钮、标题命名、图片编号、旧ID访问、更新/重试路径及导出编写有效回归，观察旧实现失败，再修复。
4. 在真实备份的隔离副本上整理。更新所有清单、正文相对链接、阅读页、PDF入口、兼容索引及历史引用；验证原件哈希和回退。
5. 正式发布核对过的条目目录和旧库归档。核对全库ID、原件、队列、标签/收藏、校订历史；新进程读回与重复运行不再迁移。
6. 完成类型、构建、相关及完整回归；真实离线页面、PDF、全文与导出检查，检查窗口尺寸和操作可见性。更新既有目录说明及本计划执行状态。
