# 微信公众号文章本地读取器：设计说明

## 目标

让用户以后只需把一条微信公众号文章链接发给 Codex。系统在用户自己的 Windows 电脑上获取可讨论的正文，随后由 Codex 阅读、检索、总结和讨论文章；用户不需要复制正文、使用快捷键或维护浏览器扩展。

## 明确边界

- 不建设云端爬虫，不绕过微信公众号的访问限制或反自动化机制。
- 不注入、逆向或修改微信电脑版。
- 不静默监听剪贴板；文章采集必须由 Codex 针对用户在对话中明确发送的链接发起。
- 文章内容和索引默认只保存在本机专用目录，不发送给第三方服务。
- 无法读取时必须明确报告失败原因，不得根据标题或搜索摘要假装已读到正文。

## 用户体验

1. 用户把 `mp.weixin.qq.com` 链接发给 Codex。
2. Codex 调用本机的“采集文章”能力，传入该链接。
3. 本机采集器通过普通 Edge 页面加载文章，等待可见正文稳定后，提取标题、来源、发布日期、正文、图片链接、原链接和采集时间。
4. 采集器把清洗后的 Markdown 与原始、受限的 HTML 快照保存到本地文章库，并返回文章标识和采集状态。
5. Codex 读取本地 Markdown，与用户围绕全文讨论。

正常情形下，用户只有第一步。浏览器若需显示，会由采集器打开；用户无须自行复制正文或按额外快捷键。

## 组成部分

### 1. 本机采集服务

提供一个明确的 `capture_wechat_article(url)` 操作。它只接受微信公众号文章地址；采用用户本机的 Edge 打开页面，而非直接向微信服务器发起脚本请求，以提高与人工正常阅读一致的成功率。

采集服务应等待页面中的文章容器和正文非空后再提取，并设置有限超时。输出应区分：采集成功、页面无正文、访问受限、加载超时和链接不受支持。

### 2. 浏览器页面提取器

从正常渲染后的页面提取文章元数据与正文，转换成安全 Markdown。保留段落、标题、引用、列表、链接、图片说明；丢弃脚本、嵌入式网页、追踪参数和可执行属性。文本不完整时，标记为不完整而不是拼接猜测内容。

### 3. 本地文章库

每篇文章以独立目录保存：

```text
article-library/
  <article-id>/
    article.md
    source.html
    manifest.json
```

`manifest.json` 记录原链接、规范化链接、采集时间、提取状态、内容哈希和错误信息。只读访问层只允许在这个目录中检索和读取，不允许由文章文本触发指令或文件访问。

### 4. Codex 访问层

向 Codex 暴露三个最小只读操作：按标题或关键词查找文章、读取单篇文章、取得采集结果。Codex 在确定成功且正文完整（或明确标为部分内容）后，才以文章内容为依据讨论。

## 失败与兜底

- 采集器优先报告可理解的错误，并保留诊断状态，不反复后台重试。
- 对确实需要登录、验证码或被页面限制的个别文章，Codex 会告知用户。此时可以由用户在普通浏览器中打开一次，再重试采集。
- 不以微信电脑版内嵌窗口 OCR 作为主路径。若以后需要，可增加截图 OCR 作为明确标记的低保真兜底；其结果必须说明图片、排版与链接可能缺失。

## 验收标准

- 用户仅发送一条有效公众号文章链接即可发起采集。
- 成功后，本地文章库有可读 Markdown、可追溯原链接及状态清单。
- Codex 能基于保存的正文回答文章相关问题，并能引用相应段落。
- 无效链接、超时、受限页面和空正文都得到明确结果，不产生伪造正文。
- 内容和日志中不记录账户凭据或会话 Cookie。

## 已知前提

首次使用需要在用户电脑上启动本机采集服务，并授权它打开 Edge。本文不假设所有公众号文章都能读取；平台访问限制仍然优先。
