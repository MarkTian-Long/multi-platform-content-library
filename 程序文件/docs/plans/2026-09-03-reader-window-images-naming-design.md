# 公众号文章阅读器：窗口、图片与命名设计

## 目标

把现有的本机公众号读取器变成可双击启动的 Windows 小窗口。用户不必打开 Codex 对话：粘贴文章链接并点击“读取文章”即可获得本地保存的、可阅读的文章与图片。

## 用户体验

启动入口是项目目录中的一个 Windows 启动文件。它打开一个轻量、独立的小窗口，包含：

- 一个公众号链接输入框；
- “读取文章”按钮；
- 明确的状态区：正在打开 Edge、正在提取正文、正在保存图片、完成或失败原因；
- 成功后显示文章标题，并提供“打开文章”和“打开保存位置”按钮。

窗口只在用户点击“读取文章”后读取输入框里的链接；不读取剪贴板、不驻留监听，也不需要 Codex 对话参与。专用 Edge 会话仍可在读取期间出现，以保留当前与人工阅读一致的采集方式。

## 技术选择

使用 Windows PowerShell 的 WinForms 作为最小桌面壳，调用现有 Node/TypeScript 读取核心。它不增加 Electron 运行时、不会额外占用 C 盘，也不需要包装或安装一个大型桌面框架。窗口和核心之间通过一个一次性的 Node CLI 命令传递 URL 与 JSON 结果；进度以阶段性状态显示，避免长期阻塞 UI。

不选择浏览器本地页，因为用户明确需要独立窗口；不选择 Electron，因为此阶段不需要复杂多窗口、托盘、自动更新或富文本编辑能力。

## 图片规则

正文提取器必须优先使用微信图片的真实延迟加载地址（例如 `data-src`、`data-original` 或 `data-actualsrc`），而不是 `src` 中的透明占位 SVG。

每篇文章保存时，为每个有效的 HTTP(S) 图片尝试保存一份本地副本到文章目录的 `images/`。Markdown 引用本地图片；若下载失败，保留原始 URL 并以清晰文本标记失败，绝不把占位图标为已获取图片。图片下载仅针对用户显式提交并正在采集的文章。

## 可读命名与迁移

项目显示名称改为“公众号文章阅读器”。数据根目录从 `article-library/` 改为 `文章库/`。

新文章目录采用：

```text
YYYY-MM-DD_<安全截断标题>_<短内容标识>/
  article.md
  source.html
  manifest.json
  images/
```

短内容标识保留唯一性与稳定读取能力；`manifest.json` 保留完整 `articleId`。标题经过 Windows 文件名清洗和长度限制。启动时运行一次受限迁移：只扫描旧 `article-library/` 下格式正确且包含 `manifest.json` 的文章，将它们改名移动到 `文章库/`；异常项目不删除、报告为迁移失败。已采集的“对话兰小欢”文章也应迁移。

## 失败与验证

- 无效链接、正文为空、Edge 超时和图片下载失败都必须在窗口中以可理解的中文报告。
- 图片下载失败不影响文字正文的 `complete` 状态，但在结果中单独标记。
- 测试覆盖延迟加载图片选择、占位图拒绝、可读目录生成、迁移约束、CLI JSON 合同和窗口启动脚本的静态契约。
- 采用真实用户提供的公众号链接做一次最终验收：验证文字正文、至少一张可获取图片或明确的图片失败状态，以及窗口生成的文章目录。

## 范围外

- 不修改或注入微信电脑版。
- 不监听剪贴板、不做后台自动采集。
- 不下载或安装 Electron，不打包安装程序，不加入自动更新。
- 不推送远程仓库或部署。
