# 资料库目录说明

当前存储已统一到 `资料库/items/`。日常使用根目录的 `多平台资料库.exe`；阅读资料时打开条目里的 `阅读.html` 或 `阅读.pdf`。

```text
多平台资料库/
├─ 多平台资料库.exe          日常入口，启动时不需要黑色终端
├─ 启动多平台资料库.cmd      旧启动方式，兼容保留
├─ README.md / CHANGELOG.md   使用与版本说明
├─ 程序文件/
│  ├─ src/                   TypeScript业务逻辑
│  ├─ link-window.ps1        Windows窗口与交互
│  ├─ launcher/              无控制台启动器源码
│  ├─ scripts/               构建、工具安装、维护与核验
│  ├─ tests/                 回归测试
│  ├─ docs/                  操作、架构、计划与验收记录
│  ├─ dist/                  构建后的运行代码
│  └─ tools、模型、依赖、专用浏览器与logs/  本机运行材料
├─ 资料库/
│  ├─ items/                 所有平台的正式资料
│  ├─ staging/               未完成任务与恢复材料
│  ├─ queue.json             采集队列
│  └─ .library-layout.json   目录版本标记，交由程序维护
├─ 文章库/                   旧微信客户端的隔离兼容资料
└─ 版本备份/                 完整恢复ZIP、快速回退与早期迁移备份
```

`src/` 的主要分工：`content-input/acquisition/service`负责链接解析、采集和任务流程；`content-library/naming/paths`负责入库、命名、哈希与引用；`content-render/reading`负责阅读页和当前PDF选择；`content-enrichment`及相关模块负责OCR和转写；`content-jobs/organization/transcript-edit`负责队列、收藏标签、导出与校订；`article-*`和`mcp/`保留微信接口。界面仍使用WinForms，黑色窗口由启动方式决定，无需更换界面框架。

## 单条资料

```text
平台 - 标题 [短编号]/
├─ 阅读.html                 当前离线阅读页，支持媒体播放
├─ 阅读.pdf                  当前阅读PDF；存在PDF的条目统一使用此文件
├─ 原始资料/
│  ├─ 正文.md                带离线相对链接的原始正文副本
│  ├─ 图片、视频、音频等/    原件，保持实际格式和字节
│  └─ 采集记录/              微信原始页面、采集正文、采集清单原样留存
├─ 处理结果/
│  ├─ 资料正文.md            正文加OCR/文字稿
│  └─ 图片文字、文字稿、截图等/
├─ 历史版本/
│  ├─ 阅读/                  已替换的旧PDF
│  ├─ 清单/                  有意义的旧清单及迁移前审计清单
│  └─ 原件/                  后续采集改变原件时，先保全旧字节
├─ .内部/                    机器处理来源、原始识别JSON等
├─ content.json              正式索引和资产哈希，程序维护
└─ manifest.json             微信接口兼容索引，仅微信条目有
```

本地原件模式不会因为入库而强制新增PDF。原始采集记录用于追溯；日常离线阅读用当前阅读页，带重写链接的正文副本也能找到原图。机器原稿、人工校订及其专用历史继续保留。

原先的 `阅读.pdf` 和 `阅读 (2).pdf` 是不同的生成版本，并非相同字节的重复文件。现在当前版本统一为根目录 `阅读.pdf`，两份旧文件移入历史目录，未直接丢弃。打印隐藏管理卡片和正文中已出现过的重复图片，保留正文OCR、补充图片及音视频原件入口。

## 统一存储与兼容范围

新版微信采集直接写入正式库，旧文章ID继续可查。`文章库/.unified-library.json`指向同项目正式库，新进程从这里读取映射。此前已运行的MCP进程缓存旧代码，保持隔离目录至其自然重启，未强制关闭已有会话。

兼容目录中的图片不能与正式原件做硬链接：旧代码可能原地改写图片。已核验相同字节的PDF和视频可安全共享存储，因为旧代码写入这些格式时使用新文件或拒绝覆盖。两处文件名保留用于兼容，19份副本共享77,498,177字节；这不包含备份占用。

普通处理中间保存不再逐步堆积历史清单。现有101份历史快照中，只移除了同一次采集、原件和派生字节均已被当前版本覆盖的80份中间快照；保留21份原有快照及17份迁移前审计清单。用户校订历史不参与此清理。

未知staging仍需保留，它们可能用于失败恢复或保全未正式入库的内容。依赖、模型、专用登录资料和Git历史有各自用途，本轮未按体积清除。

## 本轮备份与回退

`版本备份/存储优化-20261016-084810/`包含：

- `迁移前完整备份.zip`：1,133文件，含完整新旧资料库、当时源码与构建。写入后以及收尾前两次逐条回读核验SHA-256。
- `备份核验.json`、`收尾前备份复验.json`：完整清单和核验结果。
- `工作回退/原目录`及`兼容原文件`：快速回退材料；`迁移日志.json`记录每项发布状态。
- `早期迁移备份/`：从资料库根集中移来的已完成命名和平台识别备份，内容未删除。
- `演练核验.json`、`整理结果统计.json`、`收尾记录.json`：演练、清理和数量证据。

先在从ZIP恢复的真实副本上迁移，再连续回退两次；恢复文件清单与迁移前相同。正式回退入口是 `scripts/upgrade-storage.ts <项目绝对目录> rollback <迁移日志绝对路径>`，应由维护流程执行。回退会核对当前目录、原目录及兼容文件；已有新增或修改时拒绝覆盖，保留双方资料供核对。

本轮演练目录和迁移准备区已经核验清除。完整ZIP与快速回退材料有不同恢复用途，仍保留。

## 后续维护时复用

本节是项目存储维护细则的主位置，供下一次新增布局、去重或回退功能时使用；日常阅读和小范围文字更新不运行迁移。

- 共享文件前检查全部仍可能运行的写入方。旧代码会原地写图片时，保持隔离副本；不能只凭相同哈希就做硬链接。使用“临时文件加替换”或拒绝覆盖的格式，也须先核对实际实现和字节。
- 改目录要同时更新清单、Markdown、HTML、当前PDF、导出和恢复路径。路径映射覆盖本轮保全的所有文件，包括只被历史快照引用、已退出当前资产列表的旧文件。
- 回退先完整预检，再按目录实际状态和签名协调日志中断点。重复回退不删除已恢复文件；发现迁移后的新增或修改就保留双方，拒绝覆盖。
- 项目整体改名后，相对阅读引用仍可用；旧迁移日志中的绝对项目及备份路径仍是当时的证据，工具会拒绝不一致的目标。保留原日志，不批量替换历史路径；需要恢复时先用完整ZIP在隔离目录核对，再由维护流程处理迁移位置。

这些结论已由本项目代码、回归及上述正式验收承接。通用的备份、恢复预检和消费者检查沿用现有变更恢复方法，不另建用户级规则或Skill；跨项目效果待下一次真实同类任务验证。
