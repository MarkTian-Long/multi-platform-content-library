# 2026-09-06 修复与验收

## 已确认的问题

Windows PowerShell 5.1 的 BackgroundWorker 回调在线程上没有 PowerShell runspace，即使不调用浏览器也会失败。这是截图“读取失败：程序发生错误。”的可复现根因。搜索框 PlaceholderText 也不受该版本 WinForms 支持。

早前沙箱内的 ERR_NETWORK_ACCESS_DENIED 不能证明用户电脑 Edge 的网络配置故障。沙箱外已正常打开用户提供的准确链接。截图最初人工转写还混淆了小写 l 与大写 I，后续实测均使用用户提供的准确文本链接。

## 实施结果

- 改为独立 Node 进程和界面线程上的 Timer 轮询，双路异步读取 stdout/stderr，处理非零退出、空输出和无效 JSON。
- 修复中文及参数传递兼容问题；提供可取消任务、耗时提示、错误日志和不丢失结果的文章列表刷新。
- 取消列表搜索不会自动重启搜索；停止进程失败时保留任务追踪，避免启动重叠任务。
- 调整窗口颜色、尺寸、按钮布局和拉伸行为；增加打开 PDF、本篇文件夹及重新生成 PDF。
- 准确区分正文、图片、视频和 PDF 的结果。PDF 再生成失败时保留已有文件及打开路径。
- 视频按正文位置识别并去重；支持有大小、数量、时间及并发限制的公开视频直链流式下载。已成功文件可复用，失败保留原文入口。
- 等待原生播放器完成正常初始化/地址切换，最长 15 秒；即使等待超时仍保留正文。播放器暂时出错不会提前结束等待。
- 优先采用微信播放器容器的稳定视频 ID，地址切换后仍可识别同一段并复用已存文件。
- 检查完整响应范围和文件长度，拒绝仅含片段的 HTTP 206、截短或超出声明长度的响应，清理本次未完成文件。
- 以完整的微信播放器容器替换视频占位，清除播放器关注、倍速、进度条等杂字，保留容器外正文。
- PDF 不运行原页面脚本或加载远程播放器；限制大图高度并清理空装饰内容。

### 403 进一步排查

早前 0/8、HTTP 403 是当时的实际结果，但不能由此推断永久无法保存。继续实测记录如下：

1. 正常浏览器可加载 8 段，普通 Node 请求也能返回 200；不需要修改请求头、代理或导入 Cookie。
2. 全新浏览器资料下，旧采集流程复现 6/8 成功、最后两段 403。只读观察确认浏览器自身对这两条初始地址也收到 403，随后由微信播放器正常切换地址；新地址返回 200/206、视频可播放。这直接证明“过早提取初始地址并关闭页面”会错过正常恢复。
3. 修复后使用全新专用浏览器资料、独立空文章库和正式 capture/save 流程，已重复取得 8/8 HTTP 200 完整下载；不依赖原文章库的视频复用。
4. 真实 PowerShell 5.1 窗口调度流程再次返回 `complete`，提示“文章与 PDF 已保存到本地，4 张图片、8 个视频已保存”。
5. 最终全新下载的 8 个文件与正式文章库文件 SHA-256 全部一致。禁止网络的独立 Edge 中，8 段均以 4 倍速从头播放至 `ended=true`，无 HTTP(S) 请求；时长分别约 27.47、28.05、30.08、20.05、30.10、18.09、18.09、14.97 秒。完整报告：[video-live-verification-2NfJac/report.json](../logs/video-live-verification-2NfJac/report.json)。早一轮第 8 段在 16 倍速下超时；改用 4 倍速验证同一哈希文件通过，没有因此替换正式文件。

实现遵循先复现失败测试、再最小修改、最后全量测试和实际媒体核验。复审发现的“已有 metadata 但仍有 media error 不应提前结束等待”也已补回归并修复。

诊断只记录媒体域名、视频 ID、时间、状态、长度和哈希；不记录临时签名链接。服务器为何拒绝某一初始播放地址没有足够证据定性，也没有将它归咎于用户代理或账号。修复的是已复现的播放器兼容性问题，不承诺下载所有受限或加密视频。
