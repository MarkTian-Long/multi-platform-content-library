# 目录与文件规范

2026-10-21统一为第三版资料库，当前项目树、单条资料树及恢复边界见[存储目录说明](storage-layout.md)。2026-10-16第二版[验收](reviews/2026-10-16-storage-unification.md)保留历史身份；当时图片与视频位于`原始资料/`内，第三版直接按类型放在条目下，稳定ID和原件格式不变。

根README是用户入口，`程序文件/docs/`是说明与验收主位置。历史计划保留原阶段，当前功能以`platform-support.md`及总控升级计划末节为准。

## 根目录

| 路径 | 规则 |
| --- | --- |
| `多平台资料库.exe` | 日常无控制台入口；由Windows构建生成，不提交Git |
| `启动多平台资料库.cmd` | 旧版兼容入口，日常使用EXE；旧微信启动器放`程序文件/legacy/` |
| `README.md`、`CHANGELOG.md` | 安装、使用和版本入口 |
| `程序文件/` | 代码、脚本、测试、文档，以及被忽略的本机运行目录 |
| `资料库/` | 正式资料、items、queue.json、staging、history、组织与校订记录 |
| `版本备份/单库整理-20261021/旧文章库/` | 原微信库完整归档；新旧接口均读取正式资料库 |
| `版本备份/` | 完整资料/源码ZIP及快速回退材料，带文件哈希并回读核验 |
| `.git/`、`.gitignore`、`.gitattributes` | Git历史、同步排除和换行规则 |

不在根目录堆放下载样本、截图、模型、临时脚本或重复启动器。独立实验和诊断放`程序文件/logs/<用途或日期>/`，完成后按实际归属清理。

## 程序目录与GitHub同步

`src/`、`scripts/`、`tests/`、`docs/`、`legacy/`、`launcher/`、窗口脚本、package/lock/tsconfig和本目录README随源码同步。模块名称、src到dist路径、兼容入口和环境变量属于程序接口，不能为中文命名随意改动。

根目录`多平台资料库.exe`及程序目录`node_modules/`、`dist/`、`tools/`、`.venv-content/`、`logs/`、日志归档、专用浏览器目录、`.content-settings.json`、`.content-parser-auth.json`和环境文件仅留本机。下载源码后以`npm ci`、build和工具准备重建运行目录。正式资料、账号、模型和源码恢复ZIP不进入GitHub提交；GitHub源码同步不等于用户资料备份。

`.cmd`和`.ps1`工作文件使用CRLF；PowerShell 5.1中文脚本保留UTF-8 BOM。其他文本源码按Git换行规则存储；不要为格式规则改写资产字节、原件扩展名或机器原稿。

## 正式资料命名

第三版条目目录由应用生成`YYYY-MM-DD_平台_标题`，日期取北京时间的采集日期，同名用`(2)`等序号；文件名处理Windows保留名、非法字符和长度。当前文档为`标题.md`、`标题.html`和已有的`标题.pdf`；文章Markdown为整篇正文，OCR独立保存。原件按实际格式分类保存，稳定contentId/assetId、相对路径与哈希由清单维护。

小红书/抖音图集原图保留源序号（例如`图片/原图003.webp`及“第3张原图”标签），实况动态另存`视频/`并标明对应第几张。已存在的可读路径在重试时保持稳定，动态资产键同时包含目标、原序号及图片资源身份，避免同图片重复出现时覆盖；图片/动态保持平台下发字节，不合并成手机相册复合包。事务副本只在核验并原子提交后回收，原件模式不新增PDF。

小红书原对象为HEIC/HEIF时保留真实扩展名，例如`图片/原图001.heic`，平台网页预览另存`图片/预览001.webp`并标“第1张网页预览”。升级既有图片时直接复用哈希、尺寸与来源均通过的旧网页图作为预览，已有可读路径保持稳定，不再下载或保存重复预览文件。预览不是原图替代品；清单的`quality`记录文件实测尺寸、来源声明尺寸、版本及水印证据，签名URL不进入该字段。未知水印保持未知，照片/视频资源身份摘要约束防降级复用。

不要直接移动正式资产或编辑content.json改名。改标题、校订、术语替换、命名整理和导出从窗口/CLI/MCP操作，使引用、PDF、哈希及恢复记录一起更新。机器/平台原稿、用户校订和历史版本分别保留。

## 清理规则

staging只有在正式资产已完整覆盖、哈希一致且任务状态允许时回收；等待/进行中、失败恢复材料和未知文件保留。旧日志先规划、核验归档并保存恢复记录，独有诊断结果和真实夹具不按体积删除。

本次收尾只删除已停止旧测试profile的BrowserMetrics统计文件，以及与正式资料哈希一致的非正式stage/staging PDF副本。账号、原稿、报告和恢复ZIP保留。删除前核对解析绝对路径、无链接、无占用和哈希，之后对照正式库；具体清单见[清理记录](workspace-cleanup.md)。
