# 多平台资料库

## 日常使用

双击根目录唯一的日常入口 [启动多平台资料库.cmd](启动多平台资料库.cmd)。

1. 在“采集任务”中粘贴链接或完整分享文案，点击“保存链接”，一次完成入队和开始保存。需要先收集链接时，可选“仅加入队列”。
2. 当前任务与历史记录分开显示；通过“查看历史”查找已完成或失败的记录，并按需重试。
3. 在“资料库”中搜索、打开离线阅读页/媒体/PDF，或导出资料包；只有提示“缺少工具”或“需要登录”时，才打开“登录与依赖”。

新资料保存在 `资料库/`。应用只处理用户主动提交的链接；登录、验证码、付费内容、临时失效地址和平台限制可能导致部分产物不可用。每条任务会区分已保存、部分保存、需要登录、缺少工具和失败，实际平台范围以[验收报告](程序文件/docs/link-library-acceptance.md)为准。

详细操作、工具安装、命令行和上限见[操作手册](程序文件/docs/link-library-manual.md)，项目边界、资料流向和平台范围见[项目说明](程序文件/docs/project-overview.md)。首次缺少本地工具时，可在窗口点击“安装到应用目录”。

## 旧公众号阅读器

旧阅读器、已有 `文章库/` 数据和微信采集兼容存储保留；日常入口已收敛到多平台资料库，新窗口也会按兼容规则读取已有微信文章。旧启动器已可逆移动到 `程序文件/legacy/启动公众号文章阅读器.cmd`，需要维护旧微信文章时可从那里启动。它会把项目根作为 `-ProjectRoot`，仍使用根目录 `文章库/`，不会移动或删除已有文章。

技术文件、依赖、日志、模型和开发文档集中在 `程序文件/`；`文章库/` 与 `资料库/` 是用户资料目录。清理审计和未移动内容见[工作区清理记录](程序文件/docs/workspace-cleanup.md)。

## 维护

在 `程序文件/` 中执行：

```powershell
cmd /c npm run build
cmd /c npm test
cmd /c npm run typecheck
node dist/link-cli.js doctor
```

构建后再双击根目录启动器。需要 Node.js、Microsoft Edge 和 Windows PowerShell 5.1；离线语音工具另需项目专用 Python 环境。应用不读取默认浏览器资料，不监听剪贴板，也不调用云端 AI API。
